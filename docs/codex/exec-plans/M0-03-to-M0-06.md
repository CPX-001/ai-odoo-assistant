# ExecPlan M0-03 a M0-06

## Objetivo

Completar los contratos agénticos y ports mínimos de M0, automatizar la exportación de JSON Schema y las boundaries arquitectónicas, y ejecutar la gate integral sin introducir features de M1+.

## Estado inicial

- Rama única del milestone: `codex/m0`.
- M0-01 y M0-02 implementadas.
- Package `service/src/odoo_ai` importable con Pydantic v2.
- `ScreenContext`, `RecordRef` y `Evidence` públicos.
- Baseline inicial: 15 tests verdes; Ruff y mypy estricto verdes.
- No existen todavía contratos agénticos, ports ni tests automáticos de boundaries.

## Decisiones

- Modelar sólo los auxiliares explícitos necesarios para que `ContextPack` tenga fronteras tipadas.
- Representar `proposed_action` con un resumen estructurado sin lógica de writes ni approvals.
- Definir ports como `Protocol` async, sin `runtime_checkable` ni adapters concretos.
- Añadir únicamente los contratos de request/result imprescindibles para tipar los ports de Odoo y logs.
- Exportar JSON Schema mediante una función determinista; no persistir snapshots en M0.
- Verificar boundaries mediante AST y stdlib, sin añadir una librería de arquitectura.

## Progreso

- [x] Inspección inicial, task packets y Source of Truth.
- [x] M0-03: contratos agénticos.
- [x] M0-04: ports.
- [x] M0-05: schemas y boundary tests.
- [x] M0-06: gate integral y cierre documental.

## Descubrimientos

- El Source of Truth fija la forma conceptual de `ContextPack`, `ReasoningEngine`, `LogSearchRequest` y `LogEvidence`.
- `OdooGateway` queda deliberadamente abierto en nombre exacto, pero debe evitar cualquier método genérico.
- El README de M0 todavía describe el milestone como no implementado y deberá actualizarse sólo después de superar la gate.

## Riesgos

- Evitar que auxiliares de M0 congelen prematuramente schemas runtime o el diseño de writes de M6.
- Mantener los ports acotados sin degradar sus fronteras a `dict[str, Any]`.
- Asegurar que los tests de boundaries distingan imports internos permitidos de adapters prohibidos.

## Acceptance criteria

- Contratos públicos M0 y ports mínimos presentes y exportados.
- JSON Schemas reproducibles y serializables.
- Boundaries principales cubiertas por tests automáticos.
- Pytest, Ruff y mypy verdes.
- Ausencia verificada de features e imports de M1+.
- M0 marcado DONE sólo después de completar la gate M0-06.

## Resultado

PASS. M0 cumple sus acceptance criteria y el repositorio puede iniciar M1 mediante un task packet separado.
