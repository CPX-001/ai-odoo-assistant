# P5.5 post-effect reasoning

Date: 2026-08-29

Inspected baseline: `69041fd0f93bd064d924c7a4440e6bd9b2b11577`

## Objective

Replace deterministic host completion prose after a verified effect with one bounded provider continuation:

```text
execute -> verify -> authoritative verified receipt -> reason again -> natural final answer
```

The continuation may use the effective READ/reasoning capability catalog, but it must not acquire a second PLAN/effect opportunity from the already-authorized turn.

## Reused infrastructure

P5.5 reuses the existing ADR-019 host-owned decision loop, `CapabilityPlanService`, durable working transcript, P2 failure normalization, P3 public activity, P4 final-answer streaming boundary, P5.3 turn settings snapshot and P5.4 final-answer reconciliation.

No new tool registry, effect executor, approval path, persistence model or provider runtime is introduced.

## Implementation

### Authoritative receipt

After `CapabilityPlanService.execute()` has completed execution and verification, the host appends `verified_effect_receipt` to the private working transcript. The receipt includes bounded per-step capability/title plus authoritative result and verification summaries. If that item would exceed transcript bounds, the host falls back to a compact verified receipt rather than forwarding an unbounded payload.

### Post-effect provider boundary

`PostEffectDecisionEngine` gives the provider the existing REASONING catalog and working transcript but supplies an empty planning catalog. A provider attempt to return another `PlanStepProposal` is rejected through the normal host validation/correction path.

This keeps the product capable of additional read-only grounding after the effect while preventing a completed effect from being repeated merely because the provider continues reasoning.

### Final synthesis

The embedded host loop starts a fresh bounded provider decision continuation after verification. The verified receipt is already present in the transcript, the same turn snapshot/model is reused, and the provider produces the natural final answer. Public activity reports sanitized post-effect synthesis state; it does not expose private reasoning.

Provider failures after verification are normalized with `effect_state=confirmed`, so they are never treated as an effect-safe blind retry opportunity.

## Invariants

- Effect execution and verification remain host-owned.
- The durable write barrier remains the recovery boundary.
- A verified receipt is data/context, not new authority.
- Post-effect continuation has no PLAN catalog and cannot authorize or repeat a completed effect.
- Additional reasoning calls, if any, are restricted to currently effective REASONING capabilities under the same `su=False` user Environment.
- The final browser plan/receipt remains the verified completed plan; only the user-facing final prose is synthesized naturally.
- P5.6 conversation-context work is not part of this slice.

## Deterministic coverage

`test_post_effect_reasoning.py` covers the complete bounded contract rather than only the happy path:

- verified receipts preserve bounded result + verification context;
- oversized authoritative receipts degrade to a compact verified receipt instead of leaking an unbounded result;
- provider continuation is rejected before invocation when no verified receipt exists;
- the post-effect provider sees no planning catalog;
- an attempted repeated plan proposal is rejected and not executed;
- the provider can then return a natural final answer;
- the target record remains unchanged by the rejected repeat proposal;
- a provider failure after verification is normalized with `effect_state=confirmed`.
