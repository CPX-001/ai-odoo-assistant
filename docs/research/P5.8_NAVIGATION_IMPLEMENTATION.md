# P5.8 contextual navigation implementation

Date: 2026-08-30  
State: `REAL_ENV_VALIDATION_REQUIRED`

## 1. Scope

P5.8 extends the accepted record/model reference seam with contextual navigation that remains entirely host-resolved and Odoo-authoritative.

Supported public kinds are:

```text
odoo_record
odoo_model
odoo_action
odoo_view
odoo_menu
odoo_setting
```

This work is separate from turn intervention/Stop. A correction changes the active Assistant turn; a navigation reference only helps the user open a validated Odoo surface.

## 2. Resolution capability

`odoo.resolve_navigation` is a normal read-only `CapabilityDefinition` discovered through the existing provider package. No parallel tool registry was introduced.

The model may provide only:

```text
query: semantic text
kinds: optional bounded subset
limit: optional bounded result count
```

It cannot provide an action/view/menu/setting id as authority. The capability searches bounded Odoo metadata under the effective user with `su=False` and returns host-resolved typed references.

Resolution sources are deliberately narrow:

- eligible runtime models via the existing model discovery helpers;
- `ir.actions.act_window` actions whose target model remains readable;
- safe associated Odoo views with a supported view type;
- currently visible menus from Odoo menu visibility;
- installed `res.config.settings` fields backed by an available settings action.

Labels and descriptions come from current Odoo metadata/user language. Search does not expose arbitrary technical execution or routes.

## 3. Two-stage navigation authority

Discovery does not authorize browser navigation. The flow is:

```text
model asks odoo.resolve_navigation(query)
        |
        v
Odoo returns bounded typed presentation references
        |
        +-- references may appear in streaming semantic activity
        +-- references are captured structurally for the final turn response
        v
browser user selects a reference
        |
        v
/odoo_ai/v1/public-references
        |
        +-- exact-key/type validation
        +-- current user/company context
        +-- current ACL / record rule / group visibility
        +-- current record/action/view/menu/setting existence
        v
closed navigation descriptor
        |
        v
OWL action service
```

The browser never executes a provider/model URL. `openPublicReference()` constructs an Odoo action only from the descriptor returned by the second Odoo revalidation.

Current closed navigation modes are:

```text
record -> model + record_id
model  -> model
view   -> model + view_id + supported view_type
action -> revalidated act_window action_id
```

Menus and settings resolve to a revalidated action descriptor. Their original menu/setting identity remains presentation metadata only.

## 4. Streaming and final-answer presentation

`PublicTurnEvent` now has a bounded `references` field independent from the existing record-oriented `resource` field. `CapabilityExecutor` projects navigation results only for `odoo.resolve_navigation` after its output schema has validated successfully.

The semantic reducer keeps the latest closed references on the correlated activity item. The activity UI renders compact chips and sends a clicked reference back through the public-reference resolver before opening it.

The host loop separately captures navigation references from the validated working transcript into `odoo.ai.turn.public_reference_payload`. `_read_only_response()` and `_plan_response()` add them as a structured `references` collection beside the final prose. The final panel renders those references immediately below the response area; Markdown URLs are not used as authority.

A revoked/deleted reference fails closed and shows a discreet notice instead of reaching the action service.

## 5. Security boundaries

The implementation preserves these invariants:

- Odoo is the only navigation authority.
- Browser requests use exact closed reference shapes; additional keys fail closed.
- The model never supplies a route/URL that can be executed.
- `odoo.resolve_navigation` is read-only and runs under the effective `su=False` environment.
- Menu visibility is recomputed from Odoo before opening.
- Action/view targets are required to remain readable.
- Record references re-run existence/access checks immediately before opening.
- Settings references require the field to exist in the current installed `res.config.settings` schema and an eligible settings action.
- Navigation failures cannot change turn/business-effect success.
