# P5.6 ConversationContextManager validation runbook

Date: 2026-08-29  
Status: prepared; no executable PASS claimed yet

P5.6 is validated as one batch. Do not stop after the focused test merely to create another slice.

## 1. Required environment

Use a clean checkout of the exact `main` SHA on the normal disposable Odoo 18 Community validation environment.

Required variables for the real gate:

```text
ODOO_BIN
ODOO_CONF
ODOO_AI_ADDONS_PATH
ODOO_AI_P5_BASE_URL
ODOO_AI_P5_DB
ODOO_AI_P5_LOGIN
ODOO_AI_P5_PASSWORD
```

`ODOO_AI_P5_DB` must be a disposable database whose name starts with `odoo_ai_`.

Update the addon before executing the tests because P5.6 adds the persisted
`conversation_context_payload` field.

## 2. Focused HARD Odoo gate — `P5.6-ODOO-CONTEXT`

```bash
"$ODOO_BIN" -c "$ODOO_CONF" -d "$ODOO_AI_P5_DB" \
  --addons-path="$ODOO_AI_ADDONS_PATH" \
  -u odoo_ai_assistant \
  --test-enable \
  --test-tags '/odoo_ai_assistant:TestAssistantConversationContext' \
  --stop-after-init --log-level=test
```

Required observations:

```text
causal ordering comes from predecessor turns, not message timestamps
future queued user messages are absent from earlier turn context
late predecessor Assistant answer is present in correct causal order
rolling summary and verified-effect refs advance after terminal predecessors
non-terminal predecessor cannot be consumed as context
checkpoint is host-managed and immutable after capture
provider context stays within the 8,000-character seam
```

Acceptance requires a positive selected-test count and zero failures/errors.

Run immediately after the focused gate if it is green:

```bash
node --check tests/e2e/p5_6_continuity_browser.mjs

git diff --check

"$ODOO_BIN" -c "$ODOO_CONF" -d "$ODOO_AI_P5_DB" \
  --addons-path="$ODOO_AI_ADDONS_PATH" \
  -u odoo_ai_assistant \
  --test-enable --test-tags '/odoo_ai_assistant' \
  --stop-after-init --log-level=test
```

Validation ids:

```text
P5.6-DETERMINISTIC-REGRESSION
P5.6-FULL-ADDON-REGRESSION
```

The regression must preserve P5.2 same-conversation scheduling, P5.3 immutable execution settings, P5.4 one-final-answer UX and P5.5 post-effect continuation.

## 4. Real HARD gate — `P5-REAL-CONTINUITY`

With the managed Odoo server running on the configured loopback validation origin:

```bash
node tests/e2e/p5_6_continuity_browser.mjs \
  --gate P5-REAL-CONTINUITY
```

Required observation:

```text
first turn stores a unique conversation token
first turn completes
browser reload/reconnect occurs
same conversation is reopened
second turn recovers the exact prior token
second turn persisted context contains prior token
second turn persisted context excludes its own current question
fresh conversation does not recover/leak the token
no browser page errors occur
```

The runner prints:

```text
OBSERVED_OK_NOT_AUTOMATIC_PASS
```

Review the sanitized observation before recording formal PASS.

Do not store raw provider payloads, credentials or private reasoning in evidence.

## 5. Failure handling

If production code fails a gate:

1. repair the actual P5.6/runtime defect;
2. rerun the focused gate;
3. rerun every affected deterministic/full regression;
4. continue to the real gate in the same validation batch once green.

Do not weaken the causal/isolation assertions to get a pass.

A pure environment/harness repair may rerun only the affected environment gate when the production SHA and product assertions remain unchanged.

P5.6 becomes COMPLETE only after one coherent lineage records:

```text

P5.6-DETERMINISTIC-REGRESSION PASS
P5.6-FULL-ADDON-REGRESSION    PASS
P5-REAL-CONTINUITY            PASS after evidence review
```

After that, continue directly into P5.7 conversation-scoped preferences. Do not create an extra “P5.6 acceptance preparation” slice.
