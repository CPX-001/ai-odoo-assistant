# P5.6 ConversationContextManager validation runbook

Date: 2026-08-29  
Status: implementation/harness prepared; no executable PASS claimed yet

P5.6 is validated as **one batch**. A green focused test does not create another roadmap slice or manual stop.

## 1. Required environment

Use a clean checkout of the exact current `main` SHA on the normal disposable Odoo 18 Community validation environment.

Required variables:

```text
ODOO_BIN
ODOO_CONF
ODOO_AI_ADDONS_PATH
ODOO_AI_P5_BASE_URL
ODOO_AI_P5_DB
ODOO_AI_P5_LOGIN
ODOO_AI_P5_PASSWORD
```

`ODOO_AI_P5_DB` must start with `odoo_ai_`. The managed real gate only starts Odoo on an HTTP loopback origin.

If Odoo test logs are redirected away from stdout, use `ODOO_AI_P56_ODOO_TEST_ARGS` so the real test totals remain parseable. Optional managed-server arguments may be supplied through `ODOO_AI_P56_ODOO_SERVER_ARGS`.

P5.6 adds the persisted `conversation_context_payload` field, so the batch updates `odoo_ai_assistant` as part of both Odoo test commands.

## 2. Preferred complete batch

Stop the normal Odoo service on the validation port, then run the full remaining P5.6 chain:

```bash
cd "$REPO"
python tests/e2e/p5_6_acceptance_batch.py \
  --summary-out /tmp/p5_6_acceptance.json
```

The batch performs, without artificial micro-checkpoints:

```text
clean exact-SHA preflight
node syntax + real-gate manifest validation
compileall
full tests/unit pytest suite
failure/public-activity JS contract regressions
P5.6-ODOO-CONTEXT focused Odoo gate
P5.6-FULL-ADDON-REGRESSION complete addon gate
managed isolated loopback Odoo server
P5-REAL-CONTINUITY Chromium/provider gate
managed-server shutdown
sanitized summary generation
```

If every executable check succeeds the batch returns:

```text
PASS_PENDING_EVIDENCE_REVIEW
```

That is not formal roadmap PASS. Review the bounded browser observation and exact tested SHA first.

## 3. Focused HARD gate — `P5.6-ODOO-CONTEXT`

The batch runs:

```bash
"$ODOO_BIN" -c "$ODOO_CONF" -d "$ODOO_AI_P5_DB" \
  --addons-path="$ODOO_AI_ADDONS_PATH" \
  -u odoo_ai_assistant \
  --test-enable \
  --test-tags '/odoo_ai_assistant:TestAssistantConversationContext' \
  --stop-after-init --log-level=test
```

Required deterministic observations:

```text
causal ordering comes from predecessor turns, not message timestamps
future queued user messages are absent from earlier turn context
late predecessor Assistant answer remains in correct causal order
rolling summary and verified-effect refs advance after terminal predecessors
non-terminal predecessor cannot be consumed as context
checkpoint is host-managed and immutable after capture
provider context stays within the 8,000-character seam
```

Acceptance requires a positive selected-test count and zero failures/errors.

The same batch also runs:

```bash
python -m compileall -q addons/odoo_ai_assistant tests
python -m pytest -q tests/unit
node --check tests/e2e/p5_6_continuity_browser.mjs
python tests/e2e/p5_6_real_gate_check.py
node tests/js/failure_contract_test.mjs
node tests/js/public_activity_contract_test.mjs
git diff --check

"$ODOO_BIN" -c "$ODOO_CONF" -d "$ODOO_AI_P5_DB" \
  --addons-path="$ODOO_AI_ADDONS_PATH" \
  -u odoo_ai_assistant \
  --test-enable --test-tags '/odoo_ai_assistant' \
  --stop-after-init --log-level=test
```

Validation IDs:

```text
P5.6-DETERMINISTIC-REGRESSION
P5.6-FULL-ADDON-REGRESSION
```

Regression must preserve P5.2 same-conversation scheduling, P5.3 immutable execution settings, P5.4 one-final-answer UX and P5.5 post-effect continuation.

## 5. Real HARD gate — `P5-REAL-CONTINUITY`

The batch starts an isolated Odoo server and runs:

```bash
node tests/e2e/p5_6_continuity_browser.mjs \
  --gate P5-REAL-CONTINUITY
```

The browser:

```text
sends a unique synthetic token in Chat A
waits for the first turn to complete
reloads the Odoo web client
reopens Chat A
asks for the exact previous token
requires the same-chat provider answer to recover it
checks the persisted second-turn context contains prior context but not its current question
creates a fresh Chat B
requires Chat B not to recover/leak the token
checks browser page errors remain empty
```

The runner prints `OBSERVED_OK_NOT_AUTOMATIC_PASS`. It does not print the raw provider payload, credentials, hidden reasoning or the complete answer.

Because the current Codex App Server reasoning process is ephemeral, recovering the token after browser reconnect exercises Odoo-owned conversation continuity rather than relying on a durable provider thread.

## 6. Failure handling

If a production/runtime gate fails:

- diagnose and repair the actual P5.6/runtime defect;
- rerun the focused gate;
- rerun every affected deterministic/full regression;
- continue through the real gate in the same validation batch once green;
- do not weaken causal/isolation assertions to obtain green output;
- do not create another P5.6 product micro-slice merely because one sub-gate passed.

A pure harness/environment correction may rerun only the affected environment gate when production SHA and product assertions are unchanged.

## 7. Exit

P5.6 becomes `COMPLETE` only when one coherent lineage records:

```text
P5.6-ODOO-CONTEXT              PASS
P5.6-DETERMINISTIC-REGRESSION PASS
P5.6-FULL-ADDON-REGRESSION    PASS
P5-REAL-CONTINUITY            PASS after evidence review
```

Record exact tested SHA and actual environment/test totals. Never store credentials, raw prompts/answers, provider internals or customer data.

After all four pass, mark P5.6 `COMPLETE` and continue directly into P5.7 conversation-scoped preferences. Do not create a separate “P5.6 acceptance preparation” roadmap slice.
