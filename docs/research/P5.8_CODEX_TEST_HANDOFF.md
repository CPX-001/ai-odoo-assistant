## Stop observations

For `P5-REAL-TURN-STOP` verify:

- active + empty composer exposes square Stop with title/aria-label `Detener respuesta`;
- textarea remains editable during normal processing;
- Stop is bound to only the current Odoo turn/conversation scope;
- another active chat continues;
- Odoo records `cancel_requested/cancelled` regardless of provider process lifetime;
- live provider subturn receives best-effort `turn/interrupt` without exposing provider IDs to the browser;
- visible provisional answer text is retained with `Interrumpido`;
- an accepted Stop cannot be followed by a stale authoritative final answer.

## Intervention observations

For `P5-REAL-TURN-INTERVENTIONS` verify:

- active + text shows `Corregir instrucción`;
- correction stays on the same Odoo turn UUID;
- draft clears only after Odoo durable acknowledgment;
- multiple corrections preserve sequence;
- same `client_intervention_id` + same content does not duplicate row/message;
- same id + conflicting content fails closed;
- queued correction is consumed before first decision;
- running correction is persisted before provider control;
- a live steerable subturn receives `turn/steer` with `expectedTurnId`;
- if steer is unavailable, the disposable subturn is interrupted/restarted from durable Odoo intervention state;
- correction during `awaiting_confirmation` records rejection/supersession and the old plan never executes;
- another conversation is unaffected.

## Effect-boundary race

For `P5-REAL-TURN-EFFECT-BOUNDARY-RACE`, use a disposable reversible target and repeatedly race Stop/correction against first effect. Prefer at least 20 iterations split across both controls.

Only valid winners:

```text
CONTROL FIRST
- control is durable before barrier
- stale plan does not execute

BARRIER FIRST
- write barrier commits first
- effect may execute normally
- correction returns turn_effect_already_committed
- Stop affects remaining work only
- completed safe reversible effects may offer compensation
```

Hard failures:

```text
accepted correction + stale old effect executes
deadlock / long advisory-lock retention
duplicate intervention sequence/message for one client id
control leaking into another turn/chat
write outside normal policy/approval/verification lifecycle
```

## Compensation observations

For `P5-REAL-COMPENSATION`:

1. Execute/verify `odoo.record.patch`; confirm `Revertir cambios` only when host metadata marks compensation available.
2. Confirm explicit user confirmation is required.
3. Revert and verify prior values are restored before UI reports success.
4. Repeat for archive and unarchive where supported.
5. Modify the record after the original effect, then revert; require optimistic conflict and preservation of the later change.
6. Revoke write permission/rule after the original effect, then revert; require fail-closed behavior.
7. Confirm an effect without a safe compensator does not invent rollback.
