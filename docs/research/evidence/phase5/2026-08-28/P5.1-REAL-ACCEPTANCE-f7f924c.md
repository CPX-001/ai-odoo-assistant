## Problems found and repaired

1. The previous HOOT helper did not authenticate to the `auth='user'` route and watched body text
   instead of HOOT console completion. It now authenticates, enforces a bounded timeout, reports
   diagnostics and rejects zero matched tests. The runbook also avoids starting a long-lived server
   with unfiltered Python tests.
2. Two existing failure-presentation HOOT cases lacked translation setup. Their fixtures now patch
   translations explicitly.
3. The settings gate used ambiguous text selection. It now targets visible picker options and emits
   bounded diagnostics when the expected option is absent.
4. The real settings gate exposed a product defect: scoped fast-open could render before model catalog
   loading, leaving the selector empty. The model service now performs an eager bounded-TTL load and
   the scope open path refreshes preferences. A focused HOOT regression covers this behavior.

An early unfiltered long-server HOOT attempt was interrupted because it executed all installed Python
module tests before serving `/web/tests`; it was a validation-harness configuration error and is not
counted as a product result. All acceptance values above are from the corrected final configuration.

After acceptance, the isolated server was stopped and the exact disposable database, filestore and
temporary validation logs were removed. The pre-existing Odoo service on port 8069 remained available
and returned its normal `/web` redirect.
