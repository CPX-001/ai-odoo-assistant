## Failures found and repaired

1. Provider metadata with `defaultReasoningEffort` but no supported effort was accepted. Backend and browser normalization now reject it closed.
2. An explicit stored effort survived a successful catalog response that authoritatively advertised zero supported efforts. It is now cleared, while temporary catalog unavailability still preserves the preference.
3. Browser normalization accepted a selected effort outside the effective model's authoritative list. It now rejects the inconsistent payload.
4. Three App Server adapters duplicated model/effort thread configuration. One shared bounded helper now owns the exact `model` and `config.model_reasoning_effort` projection.
5. The new picker SCSS used CSS `min()` with `calc()`. Odoo 18's Sass compiler treated it as a numeric Sass function and broke `web.assets_web_print`. Equivalent `width` plus `max-width` bounds now compile successfully.
6. The Hoot runner used the retired `filter=` selection, and the first official selector accidentally hashed a duplicated leading `+`. Canonical suite hashes and the correct Odoo parameter form now select only `@odoo_ai_assistant`.
7. Real-browser runners assumed a single initial panel view and inspected nested menus before Owl completed rendering. They now enter a new chat from history when needed, wait for visible nested family/variant options and bind clicks with response waits.

No authorization boundary, capability authority or provider credential ownership changed.
