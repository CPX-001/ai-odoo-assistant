# P5.7 model/reasoning dropdown loading regression

Date: 2026-08-29
Result: `PASS`
Content-tested repair checkpoint: `4e72c5c7582ba05a2297e4d5079cb7fd67a778d6`

## Reproduction and cause

Real Chromium reproduced the reported behavior immediately after opening the Assistant: model and reasoning showed a loading spinner, looked clickable, but opened no menu. The autonomy picker opened normally.

The provider-backed catalog was healthy and returned six models. The failure was in the browser interaction contract: the Odoo `Dropdown` wrapper was disabled while the asynchronous catalog request was active, but the custom trigger did not expose a matching native disabled state. Odoo therefore ignored the click without visible feedback. Once the catalog finished loading, both menus opened.

## Repair

- Model and reasoning dropdowns remain openable while the catalog is loading.
- Their menus render explicit `Cargando modelos…` and `Cargando niveles…` states.
- A failed/empty catalog exposes a bounded `Reintentar` action instead of a silent inert trigger.
- Native trigger disabling is limited to the corresponding in-flight preference save.
- The addon version is `18.0.10.18.0`.
- The existing P5.3 browser gate now verifies that both menus really open.
- A deterministic XML contract protects loading, save-only disabling and retry behavior.
