## Authentication correction

The first local attempt incorrectly treated the managed per-addon fallback as an account that the
Odoo database should reconnect. ADR-020 corrects that diagnosis: account lifecycle belongs to the
installation's primary Codex session. Odoo now consumes the configured host `CODEX_HOME`
automatically, exposes read-only account state, and does not offer database activation, device
login, cancellation or logout.

Because the host session lives on DrvFS on this machine, starting App Server directly in that home
could not initialize its transient SQLite state. Status reads now use the same bounded isolation
model as product turns: only the non-symlink, size-bounded `auth.json` is copied into an ephemeral
Linux home, refresh is disabled, and the provider-owned source remains untouched.
