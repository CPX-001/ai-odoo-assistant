## Failures found and repaired

1. Two scheduler tests tried to overlap threads inside Odoo `TransactionCase`, whose shared
   `TestCursor` serializes requested cursors and blocked the test threads. The focused harness now
   checks repeated deterministic admission/double-claim attempts. The required independent-
   connection race proof remains in, and passed through, the real two-cron capacity gates.
2. Scheduler/fairness cleanup deleted turns but not independently persisted live-event rows before
   deleting disposable users. Cleanup now removes the bounded live rows first.
3. Existing P3/P4 projection fixtures deliberately committed active turns for cross-cursor
   visibility but did not remove them after the `TransactionCase` savepoint rollback. The new global
   scheduler correctly counted those stale fixtures as active capacity, breaking the full battery.
   The fixtures now register post-rollback cleanup for both live rows and committed turns.

The initial focused run reported 2 failures and 7 errors; the initial full-addon run then exposed 3
failures and 8 errors from the P3/P4 fixture leak. After the harness repairs, the affected focused
batch and complete addon regression both passed without weakening production concurrency checks.
