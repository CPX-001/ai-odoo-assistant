## Objective

Prevent a Phase 0 READ capture from being treated as functional success merely because the Odoo turn reached `completed`.

The first real `read_partner` capture completed without any capability/tool checkpoints and the browser answer reported that the Odoo query failed. That observation remains a failed `P0-REAL-READ`.

## Change

Added `tests/e2e/phase0_read_acceptance.py` plus `tests/unit/test_phase0_read_acceptance.py`.

For `read_partner`, `query_sales`, and `aggregate_sales`, the acceptance evaluator now requires all of:

- `capture_kind=live_http`;
- no request-side or capture-side error;
- final state `completed`;
- observed `tool.started`;
- observed `tool.completed`.

The evaluator consumes only already-sanitized Phase 0 traces. It does not inspect prompt text, answer text, raw tool arguments/results, provider output, credentials, or private reasoning. It does not modify product runtime behavior.

This is intentionally a minimum machine gate. The real validation still requires a human/product check that the final answer reflects the known Odoo data, per `P0-REAL-READ`.
