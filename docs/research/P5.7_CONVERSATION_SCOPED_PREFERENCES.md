# P5.7 conversation-scoped preference mutation

Date: 2026-08-29  
Status: implementation checkpoint; focused Odoo validation required before further roadmap work

## Scope

This is the remaining explicit conversation-preference sub-slice after the already accepted
model-family / model-variant / reasoning-effort work.

The implementation adds two conversation-owned preference families without creating another
agent/tool registry:

```text
temporary autonomy profile
response-language preference
```

Both reuse the existing `CapabilityDefinition -> preview/policy/execute/verify` host lifecycle.
They affect future turns only. A queued turn retains the values captured for that turn.

## Host-owned state

`odoo.ai.chat.policy` now has an explicit `autonomy_override_active` marker for a
conversation. When active, the selected conversation profile replaces the user's durable
profile only in that conversation's policy snapshot. The other host policy layers remain
present and authoritative.

`odoo.ai.conversation` now stores:

```text
response_language_mode = inherit | automatic | odoo | fixed
response_language
```

`fixed` accepts a bounded language tag such as `es`, `en`, `es_ES` or `pt-BR`; other modes
must not carry a fixed language value.

`odoo.ai.turn` snapshots those response-language fields when the durable turn is created.
Changing the conversation preference later cannot mutate an already queued turn. The captured
values are projected into P5.6 `session_settings` together with `odoo_user_language`.

## Capabilities

The built-in capability provider exposes:

```text
assistant.conversation.preferences
assistant.conversation.set_autonomy
assistant.conversation.set_response_language
```

`assistant.conversation.preferences` is read-only reasoning authority.

`assistant.conversation.set_autonomy` is a reversible PLAN effect with preview and verification,
but it always requires explicit human approval because increasing autonomy changes future effect
policy. Its input is bounded to the four existing product profiles plus `inherit`.

`assistant.conversation.set_response_language` is a reversible low-risk PLAN effect with preview
and verification. It never grants Odoo or capability authority.

All handlers resolve the current owned conversation under the effective user environment; no
sudo, generic ORM method execution, SQL, shell or second preference runtime is introduced.

This follows the Project Atlas pattern of keeping `CapabilityDefinition` as the atomic host-owned
