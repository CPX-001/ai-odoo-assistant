# P5.1 turn-scoped frontend validation runbook

Date: 2026-08-28  
Status: executable validation handoff; **not PASS evidence**

This runbook validates the landed P5.1 frontend contract without advancing into P5.2 scheduler/backpressure design.
It assumes the accepted P2-P4 foundation remains unchanged and exercises the exact current product path:

```text
real Odoo browser UI
 -> durable /turn enqueue
 -> existing two-slot ir.cron queue
 -> embedded AgentTurnService / Codex
 -> persisted activity/answer/failure
 -> per-conversation frontend scope projection
```

A successful browser script prints `OBSERVED_OK_NOT_AUTOMATIC_PASS`. Formal state changes still require review of the exact tested SHA and sanitized evidence.

## 1. What P5.1 must prove

P5.1 owns browser execution state, not scheduler policy. Before P5.2 is eligible, establish that:

```text
Chat A running does not globally lock history/new-chat navigation
Chat A running does not lock model/autonomy selectors
Chat B can be submitted independently through the existing durable queue
late A activity/deltas/failures do not overwrite B
returning to A restores A's own live/provisional state
closing/reopening the panel does not cancel or resubmit A
A keeps the model/policy snapshot captured at enqueue
B captures preference changes made after A was queued
P2/P3/P4 browser contracts still regress cleanly
```

This does **not** claim the complete Phase 5 gates `P5-REAL-MULTICHAT`, `P5-REAL-BACKPRESSURE`, ordering/fairness, post-effect synthesis or continuity. Those consume later P5 slices.

## 6. P5.1 browser gates

The machine-readable manifest is `tests/e2e/p5_1_real_gates.json`.

### P5.1-BROWSER-MULTICHAT

```bash
node tests/e2e/p5_1_turn_scope_browser.mjs --gate P5.1-BROWSER-MULTICHAT
```

The runner starts long safe Chat A, navigates to history while A is unresolved, starts Chat B, verifies distinct durable turn/conversation ids, checks both runtime badges and returns to A. Visible A/B messages must not cross scopes.

### P5.1-BROWSER-SETTINGS-SNAPSHOT

```bash
node tests/e2e/p5_1_turn_scope_browser.mjs --gate P5.1-BROWSER-SETTINGS-SNAPSHOT
```

The owning internal user can read its own `odoo.ai.turn` rows. The runner uses that existing read ACL only to compare bounded persisted fields:

```text
reasoning_model
policy_payload.layers.user
```

It captures Turn A, changes model/autonomy through the real UI while A is unresolved, proves A's persisted snapshot is unchanged, enqueues B and proves B captured the new preference values. Original preferences are restored best-effort during cleanup.

### P5.1-BROWSER-REOPEN

```bash
node tests/e2e/p5_1_turn_scope_browser.mjs --gate P5.1-BROWSER-REOPEN
```

The runner counts `/odoo_ai/v1/turn` POSTs, closes the panel while A is unresolved, waits while server work continues, reopens the panel and verifies there is still exactly one A submission and the same conversation state is visible.

## 8. Exit rule

P5.1 may move out of `LOCAL_VALIDATION_REQUIRED` only when:

```text
P5.1-HOOT-TURN-SCOPES          PASS
P5.1-P2-P4-REGRESSION          PASS
P5.1-BROWSER-MULTICHAT         PASS
P5.1-BROWSER-SETTINGS-SNAPSHOT PASS
P5.1-BROWSER-REOPEN            PASS
```

Any failure creates the smallest P5.1 repair slice. Do not begin P5.2 implementation while one of these remains failed or unexecuted.
