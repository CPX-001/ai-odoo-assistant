## 3. Current next validation slice — bounded deterministic regression

Validation ID:

```text
P5.3-DETERMINISTIC-REGRESSION
```

The regression selector is intentionally method-level so this gate stays small. Execute these exact contracts when the local Odoo test selector supports method-level targeting; otherwise run only their containing classes:

```text
TestAssistantTurnQueue.test_enqueue_persists_user_turn_and_initial_event
TestAssistantTurnQueue.test_enqueue_is_idempotent_for_client_request_id
TestAssistantUserPreferences.test_reasoning_model_is_owned_by_current_user
TestAssistantChatPolicy.test_effective_capability_policy_uses_user_autonomy_once
TestCapabilityActions.test_approve_requeues_same_turn_with_bound_authorization
TestAssistantTurnSettingsSnapshot.test_runtime_codex_settings_use_captured_turn_model
```

These cover, respectively:

```text
normal enqueue persistence
client-request idempotency
user-owned model preference isolation
profile -> resolved policy mapping
approval -> same persisted turn with original captured model/policy after preferences change
embedded runtime Codex settings reading the persisted turn model rather than current user preference
```

The approval regression must observe that changing the user from model/profile A to B while the plan waits for confirmation does not replace the turn, mutate its snapshot, or make the approval response use profile B. The runtime-consumption regression patches only Codex discovery/path facts; it does not start a provider process and must prove `_codex_settings(turn)` receives model A from the persisted turn.

If this bounded gate fails, repair only the smallest responsible P5.3/test-contract layer and rerun the affected coverage. Do not launch the browser gate to compensate for a deterministic failure.

A full `/odoo_ai_assistant` battery is required before formal P5.3 acceptance if production/model code is repaired, and in all cases before consuming the completed Phase 5 snapshot contract downstream.
