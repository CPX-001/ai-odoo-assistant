## 2. Mandatory gate now — focused Odoo only

Validation ID:

```text
P5.3-ODOO-SETTINGS-SNAPSHOT
```

Run the addon test containing:

```text
TestAssistantTurnSettingsSnapshot
```

Required observations:

```text
Turn A captures snapshot format v1
Turn A retains its model/policy/autonomy after preferences change
Turn B captures the new preferences
captured model/policy/snapshot cannot be mutated after enqueue
normal non-settings lifecycle writes still work
```

The environment/setup command may be adjusted to the local Odoo checkout/configuration, but it must actually update `odoo_ai_assistant` and execute this test class against the exact tested SHA. Do not substitute source inspection for execution.

If this gate fails, stop and repair only the smallest P5.3 ownership/validation layer. Do not run the larger regression batch first.

## 3. Next validation slice after focused PASS

Only after `P5.3-ODOO-SETTINGS-SNAPSHOT` passes, run a separate bounded regression slice covering the existing contracts most likely to be affected:

```text
turn enqueue / idempotency
user model + autonomy preferences
policy resolution
approval -> same-turn requeue/resume
embedded runtime consumption of persisted reasoning_model/policy_payload
```

A full `/odoo_ai_assistant` battery is required before formal P5.3 acceptance if production/model code was repaired, and in all cases before consuming the completed Phase 5 snapshot contract downstream.

## 4. Formal real product-path gate after deterministic regression

The Phase 5 playbook names:

```text
P5-REAL-SETTINGS-SNAPSHOT
```

Reuse the real browser behavior already exercised by the P5.1 settings-snapshot gate, but run it on the P5.3 lineage and additionally verify the versioned `execution_settings_payload`:

```text
start unresolved Turn A with model/profile A
change model/profile through the real UI
prove Turn A stored snapshot remains A
submit Turn B
prove Turn B stored snapshot is B
resume/approve A when applicable and prove it still uses A's stored policy/model
```

The prior `P5.1-BROWSER-SETTINGS-SNAPSHOT` PASS is useful supporting evidence, but it is not automatic PASS for the new P5.3 contract or SHA.

## 5. Evidence and exit

For each gate record:

```text
validation id
tested SHA
Odoo/PostgreSQL/Python version
result PASS | FAIL | BLOCKED
actual test totals
observed snapshot model/profile/policy comparison in sanitized form
repairs made, if any
```

Do not store credentials, provider auth, raw prompts, hidden reasoning or sensitive business data.

P5.3 may become COMPLETE only after its deterministic/regression coverage and `P5-REAL-SETTINGS-SNAPSHOT` pass on a coherent accepted lineage. The immediate stop boundary for the current implementation run is the focused `P5.3-ODOO-SETTINGS-SNAPSHOT` gate above.
