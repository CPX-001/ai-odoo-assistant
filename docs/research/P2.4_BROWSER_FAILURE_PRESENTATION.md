## Objective

Consume validated `browser_status().failure` without trusting arbitrary browser input, preserve its machine semantics through polling/streaming, and render deterministic recovery guidance without weakening the write barrier.

## Implemented

`static/src/services/assistant_failure_contract.js` mirrors the exact 11-field `FailureEnvelope`, closed taxonomies and host limits. Invalid, mismatched, sensitive-key or oversized details fail closed; only a bounded compatibility code may survive.

`assistant_stream_client.js` carries terminal structured failures. The streaming panel no longer converts every unknown bounded thrown code to `service_unavailable`; provisional text is still discarded on failure.

Presentation is deterministic and never renders provider text, `safe_summary` or `safe_details`. Only stable code and diagnostic id may be technical detail. Authentication, Odoo ACL, provider connection/capacity, capability, verification and recovery receive distinct behavior.

Retry is available only when:

```text
retryability == safe
effect_state in {none, not_started}
user_action == retry
```

`partial`/`unknown` and `recovery_required` never expose blind retry.
